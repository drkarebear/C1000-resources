Accessibility

I aim to make the ENGL C1000 Learning Lab usable by as many people as possible and to meet or exceed WCAG 2.2 Level AA where I control the experience.

Accessibility Practices

The site uses semantic headings and landmarks, keyboard-accessible controls, skip links, visible focus indicators, high-contrast text and controls, responsive reflow, accessible names for form controls, status messages for interactive feedback, and reduced-motion support. Activities are designed so that drag-and-drop is not required.

Some activities use optional browser features such as local storage, copy-to-clipboard controls, or speech synthesis. Browser and assistive-technology support for those features can vary. Where read-aloud is offered, it is supplemental; the same instructional text remains available visually on the page.

Testing and Ongoing Review

I use WCAG 2.2 Level AA as the project target and check for common automated-test errors, contrast problems, keyboard barriers, heading and landmark issues, reflow problems, accessible-name issues, focus problems, and interactive status-message problems.

Automated tools cannot certify legal compliance, so human review and assistive-technology testing remain part of the accessibility process. Accessibility is an ongoing practice, and I may continue refining activities as issues are identified.

Report an Accessibility Barrier

If you encounter an accessibility barrier in the Learning Lab itself, please email me about the accessibility issue and, if possible, include the page name and a short description of what was difficult to use.
